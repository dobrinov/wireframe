Why wireframes, not specs

Agree on the idea while it’s still cheap to change.

Communicate

Everyone clicks the same thing

A spec is read ten different ways. A working wireframe shows the flow, the states and the edge cases, so product, design, engineering and customers react to the same idea.

Iterate cheaply

Change it in a minute, not a sprint

Point at a problem and the agent changes it while you watch. It is grey on purpose, so feedback is about what the product does, not how it looks.

Then write it down

Spec and HiFi come last

When the wireframe is agreed, turn it into a written specification and use it as the brief for HiFi screens. The hard questions are already answered.

How it works

From a brief to an agreed wireframe to a spec.

01 · Brief

/wireframe <what you want>

A sentence is enough. If the brief is truly ambiguous, Claude asks one round of short questions. Otherwise it decides and writes its assumptions down.

02 · Build

Working, not pictures

Claude plans the screens, the data and the test users, then builds them from the wf library. Forms save, lists filter, permissions apply and every screen has its empty state.

03 · Iterate

Prompt or comment

Share it, click through it, press C and comment on anything. The agent changes it while you watch. Repeat until everyone agrees.

04 · Hand over

Spec and HiFi

Ask Claude to turn the wireframe and its WIREFRAME.md into a written spec, and give designers the agreed screens as the brief for HiFi.

Seeded users

Every prototype comes with the people who break it.

Claude picks a cast for each project: someone with no data, someone with everything, one person per role and plan, and the edge cases your brief hints at. Press U to sign in as any of them. Each one shows a different state of the product.

Each user says why it exists and what to test with it.
Realistic data whose numbers add up. For approvals and hand-offs, users share one world: what the accountant submits is waiting when you switch to the owner.
The cast evolves: add billing and a “trial expired” user appears, with a note saying why.

Comments that reach the agent

Point at the problem. Tick a box. Watch it get fixed.

Every comment carries the screen, the exact element you clicked and the user you were signed in as, so the agent sees what you saw. While it works, the comment shows who picked it up, where, and each step as it happens.

1 · In the browserPress C, click, writeThe cursor turns into a speech bubble. Tick “Send to coding agent” and an orange pin marks the spot.
2 · On your computerThe wf helper queues itEvery comment is saved with the project. Ticked ones go to the agent’s inbox.
3 · Live, on the commentWatch the agent workYour /wireframe session picks it up. If none is open, a short background run does. Either way, the steps stream onto the comment.
4 · Back on screenReload, reply, resolvedThe page refreshes, the agent replies and the pin resolves. Every thread stays under Threads (T).

Made for real product questions

From a blank idea to a feature inside an existing product.

Shared world

A request drafted by an accountant, approved by the owner and reviewed by the bank: switch users and the same record moves through every step.

Embedded apps

Questions

Good to know

Does anything leave my computer?

The prototype and the comment helper run only on your machine and accept local connections only. The agent is your normal Claude Code session.

Why is everything grey?

LoFi keeps the conversation on flows, content and states, and keeps changes cheap. Once the wireframe is agreed, it becomes the brief for HiFi design.

What if no Claude Code session is open?

Comments you send wait in the project’s inbox. After about 20 seconds the helper can start a short background run, limited to editing the prototype, and you can follow its steps on the comment. You can switch that off per project.

Can I add my own components?

Yes. Follow the style recipe (tokens only, all eight states, real HTML underneath) and run wf lint. The agent uses the same recipe.

Which computers does it run on?

Mac, Linux and Windows. Installers for all three are included and bring their own runtime when needed.
